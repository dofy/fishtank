# PixiJS 写实模式优化复测

2026-10-19，在 v1.6.0 工作区完成优化前后复测，随 v1.7.0 发布默认 PixiJS 鱼缸。两种风格、原有玩法和存档格式继续沿用。以下性能数字来自发布前的本机开发环境，线上部署记录见 [部署记录](DEPLOYMENTS.md)。

## 保留画面，减少重复工作

- 鱼体继续使用 **19×9 网格**，改用 PixiJS 原生网格合批，移除每条鱼各自的着色器与独立绘制提交。
- 将同一列重复的摆动计算合并，缓存列坐标与鳗鱼静止曲线。普通鱼、鳗鱼、海蛇、水母、蝠鲼、海龟、海马的动作公式、速度和转身过渡保持原样。
- LCD、眩晕或关闭动态效果时，网格恢复静止姿态后停止重复上传；恢复动画时再更新。
- 将滤镜范围固定到可见鱼缸，避免每帧遍历鱼、灯光和粒子计算包围盒。滤镜分辨率、抗锯齿、折射、光纹和微粒效果保留。
- 仅在状态变化时更新滤镜开关、诊断属性；没有电弧时不重复清空图形。

## 相同场景复测

Chrome 155 / macOS，Apple M5 / ANGLE Metal，DPR 1，约 75 FPS 上限。三个场景都使用黑夜、12 条鱼、9 件造景，开启鱼体摆动和水下效果。每个尺寸的**同一份序列化快照**用于优化前后，包括鱼的位置、速度、相位、朝向、品阶和造景；快照与逐帧采样见 [原始记录](PIXI_OPTIMIZATION_RAW.json)。

每次按 Canvas → PixiJS → PixiJS → Canvas 顺序重放，每轮预热 90 帧、采样 180 帧。每个渲染器有 360 个 JS / 帧间隔样本，PixiJS 有 358 个异步 GPU 样本。下面比较的是 **PixiJS 优化前与优化后**，不是与 Canvas 的比较。

| 场景（显示尺寸） | JS 均值，前 → 后 | JS P95，前 → 后 | 均值变化 | FPS，前 → 后 | GPU 均值，前 → 后 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 桌面 954×230 | 0.841 → 0.539 ms | 1.40 → 0.80 ms | 降低 35.9% | 74.96 → 74.97 | 0.565 → 0.680 ms |
| 沉浸 1280×900 | 1.244 → 0.801 ms | 1.70 → 1.70 ms | 降低 35.6% | 74.96 → 74.96 | 2.072 → 2.056 ms |
| 小屏模拟 372×185 | 0.690 → 0.743 ms | 1.10 → 1.60 ms | 增加 7.6% | 74.96 → 74.95 | 0.503 → 0.644 ms |

桌面和沉浸模式的平均 JS 开销有所下降；沉浸模式的 P95 没有改善。小屏本轮增加约 0.053 ms，GPU 均值也没有一致下降，不能宣称所有设备都更快。三种尺寸的帧率均接近刷新上限。本轮每组只进行一次 ABBA 测量，包含浏览器调度、JIT、缓存与 GPU 波动，不代表统计显著性、手机实机性能或耗电结论。

优化后同轮 Canvas JS 均值分别为 0.469 / 0.570 / 0.526 ms，仍低于保留网格摆动与额外水下滤镜的 PixiJS。默认切换基于当前画面效果、可接受的帧预算和已验证的回退能力，**不是因为写实 PixiJS 已全面快于 Canvas**。上一轮 LCD 与初次原生迁移数据见 [历史性能记录](PIXI_PERFORMANCE.md)。

## 画面与功能验证

- 58 项自动测试、类型检查与生产构建通过。新增回归检查全部 29 种鱼、多个相位、正常 / 受惊速度下的每个顶点，允许误差小于 0.00002 逻辑像素；同时检查静止后不重复上传以及动画恢复。
- 固定同一快照与 1.6 秒姿态，优化前后截图平均 RGB 绝对差约 **0.008 / 255**；没有像素的三通道平均差超过 10。画面差异主要来自合批后的浮点与光栅化细节。这是一个姿态的截图检查，并非全部动画逐帧视觉证明。
- 默认入口实测 12 条鱼、9 件造景；原有 Canvas 整缸绘制调用为 0。验证投喂、受惊、装饰拖动保存、电鳗六次点击放电与另外 11 条鱼眩晕。
- 写实 / LCD 和昼夜切换、390 宽度与沉浸模式、减少动态效果均验证；小屏无横向溢出，GPU 画面与输入画布在沉浸模式下重合。
- WebGL 上下文丢失后当帧使用 Canvas，恢复后继续 PixiJS。初始化失败、绘制异常与加载失败均保留 Canvas 路径；`?renderer=canvas` 可手动强制使用旧渲染器。
- 本地生产预览验证默认 PixiJS、LCD 切换、繁育收鱼、DPR 2 小屏，以及无 WebGL / 手动 Canvas 回退；这些流程没有页面异常。手动 Canvas 没有请求 GPU 模块，生产预览不会显示实验工具栏。开发对照的效果开关、分界滑块与窗口变化取消采样也已复核。

## 发布验证与入口

1.7.0 已发布到两个现有域名；58 项回归与构建通过。发布复查补修异步初始化后的 Service Worker 注册，以及 CF 将 `/index.html` 重定向后导致的离线导航兜底；r2 已在两域名验证在线预热刷新后断网启动 PixiJS 与 Canvas。后续 LCD 新鱼标记修补使用 r3，繁育/合成点阵光效修补使用 r4，LCD 界面与放电点阵补全使用 r5，图鉴选中项对比度补修使用缓存 `fishtank-pwa-v1.7.0-r6`。部署版本、流量与资源哈希见 [部署记录](DEPLOYMENTS.md)。

以下为开发服务入口：

- 正常游戏：<http://localhost:5173/>，默认 PixiJS。
- Canvas 回退：<http://localhost:5173/?renderer=canvas>，不加载 GPU 模块，不修改偏好或存档。
- 开发对照：<http://localhost:5173/?pixiLab=1>，保留切换、滑动比较、效果开关、示例鱼群和性能采样。

正常生产构建也已包含可按需加载的 PixiJS 模块，便于本地 `pnpm preview` 验证；实验工具栏仍仅限开发服务。相比之前只有 Canvas 的包，会多下载 GPU 运行时和着色器模块。v1.7.0 发布保留 `fishtank.phpz.org` 与 `fish.yahaha.net`，两者均提供 `?renderer=canvas` 回退入口。对照模式仅在开发服务中启用。
